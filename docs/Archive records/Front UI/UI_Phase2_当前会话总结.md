## 二、问题诊断过程

### 2.1 初步检查
1. ✅ 编译状态 - 成功（0 错误，2 个无关警告）
2. ✅ 进程状态 - 运行中但窗口不显示
3. ✅ 日志检查 - 仅显示初始化日志后立即退出

### 2.2 根因分析
通过分析 `App.axaml.cs` 发现死锁点：

```csharp
// 第 64 行 - 死锁点
var mainViewModel = (MainWindowViewModel)mainWindow.DataContext!;
mainViewModel.InitializeAsync().Wait();  // ❌ 阻塞 UI 线程
```

**死锁机制**:
```
UI 线程: OnFrameworkInitializationCompleted()
    ↓
调用: mainViewModel.InitializeAsync().Wait()
    ↓
等待异步任务完成
    ↓
异步任务内部需要回到 UI 线程 (Dispatcher)
    ↓
UI 线程被 .Wait() 阻塞，无法响应
    ↓
死锁：互相等待
```

## 三、修复实施

### 3.1 修复代码

**文件**: `src/HD2Mimnt.UI/App.axaml.cs`  
**位置**: 第 64 行

```csharp
// 修复前
mainViewModel.InitializeAsync().Wait();

// 修复后
_ = mainViewModel.InitializeAsync();
```

**修复原理**:
- 使用 fire-and-forget 模式
- UI 线程不再等待异步任务
- 窗口立即显示
- 初始化在后台异步完成

## 八、技术总结

### 8.1 关键技术点

1. **Avalonia UI 线程模型**
   - UI 线程是单线程
   - 阻塞 UI 线程会导致应用无响应或死锁
   - 使用 fire-and-forget 模式处理初始化

2. **异步初始化模式**
   ```csharp
   // ❌ 错误：阻塞 UI 线程
   await task.Wait();
   
   // ✅ 正确：fire-and-forget
   _ = task;
   
   // ✅ 正确：真正的异步
   await task;  // 但只能在 async 方法中
   ```

3. **MVVM 初始化**
   - ViewModel 初始化应该异步
   - 通过 `INotifyPropertyChanged` 更新 UI
   - 初始化期间显示加载状态

### 8.2 经验教训

1. **.Wait() 的危险性**
   - 在 UI 线程上使用 `.Wait()` 是常见的死锁原因
   - 特别是当异步方法内部需要回到 UI 线程时
   - 应该使用 async/await 或 fire-and-forget

2. **调试技巧**
   - 应用启动后立即退出 → 检查初始化代码
   - 进程存在但窗口不显示 → 检查 UI 线程阻塞
   - 查看日志可以确定执行到哪一步

3. **最佳实践**
   - 在 OnFrameworkInitializationCompleted 中只做必要的同步初始化
   - 耗时的初始化（网络请求、数据库查询）应该异步执行
   - 提供加载状态反馈
