# HD2Mimnt UI 实现说明

## 页面与 ViewModel

| 页面 | View | ViewModel | 主要服务 |
|---|---|---|---|
| 模组库 | `LibraryView` | `LibraryViewModel` | `ModService`、`SearchService`、`ProfileService`、`DeploymentService`、`GameDetectionService` |
| 配置文件 | `ProfileView` | `ProfileViewModel` | `ProfileService`、`ModService` |
| 设置 | `SettingsView` | `SettingsViewModel` | `SettingsService`、`GameDetectionService` |
| 更多 | `MoreView` | `MainWindowViewModel` | `ExternalToolService`、`PluginService`、`BackupService`、`FileLogService` |
| 任务中心 | `TaskCenterView` | `TaskCenterViewModel` | `TaskService` |
| 通知 | `NotificationPanel` | `NotificationPanelViewModel` | `NotificationService` |

## 导航与生命周期

主窗口保留一个 `MainWindowViewModel` 实例，通过四个一级导航项切换内容。任务中心和通知面板是覆盖层，不占用一级导航位置。确认对话框由单例 `ConfirmationService` 持有主窗口所有者；主窗口不在构造函数中重复创建 ViewModel。

主窗口关闭事件查询 `TaskService` 的运行中任务；存在可能被中断的任务时先由 `ConfirmationService` 明确确认，确认后才关闭窗口。

## 数据流与状态

- UI 通过 Application 层服务发起导入、配置文件、部署和清理操作。
- 模组启用状态来自当前配置文件，部署状态来自最近部署记录，两者分别显示。
- 搜索、筛选和排序在后台计算普通列表，回到 UI 上下文后整体替换 `ObservableCollection`。
- 部署和清理使用 `CancellationTokenSource`，确认后执行，覆盖层提供取消入口。
- 通知服务统一管理成功、信息、警告和错误通知，支持去重、自动过期、删除和操作按钮。
- 通知可携带统一导航目标；面板触发 `NavigationRequested`，主窗口负责关闭通知覆盖层并执行页面导航，通知服务不依赖 UI 类型。
- 备份服务以 SQLite `VACUUM INTO` 创建数据库快照并与设置文件压缩，恢复前由确认服务确认，恢复后刷新各页面数据。
- 文件日志提供者将现有 `ILogger` 输出写入应用数据目录；日志页只读取最近 500 行，导出按流复制，不把整个文件载入内存。
- 插件 manifest 由 `IPluginService` 解析，安装前展示权限请求；插件卡片可打开权限编辑对话框并调用授权/撤销服务。

## 键盘与状态

- 主窗口：`Ctrl+1` 至 `Ctrl+4` 切换一级页面，`Esc` 关闭全局覆盖层。
- 模组库：`Ctrl+F` 聚焦搜索，`Ctrl+A` 全选当前筛选结果，`Delete` 发起批量删除确认，`Enter` 打开焦点模组，`Esc` 关闭详情或清空选择。
- 模组库、配置文件、任务中心提供加载、空数据和错误状态；搜索无结果单独显示下一步操作。
- 配置文件对比使用两个配置的 `ProfileMod` 集合按 `ModId` 合并，只比较存在性和启用状态，不把版本变化误判为模组差异；结果仅供查看并支持差异类型筛选。
- 主题通过 Avalonia `ThemeDictionaries` 提供深色和浅色表面、边框、文字动态资源，切换只更新主题变体，不重建页面。
- 模组库默认排序和筛选从 `SettingsService` 读取并通过 `MainWindowViewModel` 应用到 `LibraryViewModel`；设置变化只重新计算已有集合。
- 配置详情和对比通过 `ModService.GetModsByIdsAsync` 使用参数化分块查询，只读取配置涉及的模组；配置切换通过 `CancellationTokenSource` 取消旧加载。
- 批量启用/禁用通过 `ProfileService.SetModsEnabledAsync` 一次更新 Profile；启用不存在的 ProfileMod 时自动加入并分配顺序。
- 部署清理仅在所有文件成功清理后删除 DeploymentRecord；失败目标保留记录，允许后续重试。

## 性能边界

模组列表使用 `VirtualizingStackPanel`。SQLite 基准提供 1,000/5,000/10,000 三档数据量，Release 进程资源采样由 `scripts/measure-release-ui.ps1` 统一输出。结果记录在 `docs/UI_性能基线_2026-10-03.md`，不替代真实窗口滚动、高 DPI 和长时间运行验收。
