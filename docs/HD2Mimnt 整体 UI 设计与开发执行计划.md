
# HD2Mimnt — 整体 UI 设计与开发执行计划

> 项目：HD2Mimnt
> 类型：Helldivers 2 专用模组管理器
> UI 技术：Avalonia / Jalium.UI（以仓库现有实际实现为准）
> 目标框架：.NET 10
> 架构原则：MVVM、模块化、异步操作、虚拟化、低资源占用
> 计划类型：UI 设计、实现、性能优化与验收
> 优先级：P0（必须完成）、P1（重要）、P2（后续完善）

---

# 一、项目总体目标

## 1.1 核心目标

对 HD2Mimnt 进行完整的 UI 规划与开发，建立统一、易用、高性能的桌面应用界面。

本计划不以单纯完成页面为目标，而是要求整个 UI 在实际管理大量模组时依然保持流畅，并严格控制空闲状态下的 CPU 与内存占用。

核心目标：

1. 建立统一的应用程序整体布局。
2. 完成模组库、配置文件、设置、更多四个一级页面。
3. 建立全局任务中心与统一通知系统。
4. 实现模组搜索、筛选、排序、批量操作等核心交互。
5. 实现配置文件的创建、切换、编辑和删除等交互。
6. 与现有后端服务集成，避免 UI 重复实现业务逻辑。
7. 支持大规模模组数据，避免列表加载和滚动卡顿。
8. 严格控制 CPU、内存和后台任务的资源消耗。
9. 保证页面切换、配置文件切换和批量管理操作的响应速度。
10. 建立可重复执行的性能测试与验收机制。

## 1.2 硬性性能目标

| 指标 | 目标 | 优先级 |
|---|---:|---|
| 空闲 CPU | 接近 0%，不允许持续性无效占用 | P0 |
| 空闲内存 | Working Set < 500 MB | P0 |
| 私有内存 | 监控并限制无界增长 | P0 |
| 普通 UI 交互 | 目标响应时间 ≤ 100 ms | P0 |
| 搜索与筛选 | 目标响应时间 ≤ 100 ms | P0 |
| 已缓存配置文件切换 | 目标界面响应时间 ≤ 100 ms | P0 |
| 模组列表 | 支持 10,000+ 条数据 | P0 |
| 武器、怪物等大型选择器 | 支持 8,000+ 条数据 | P0 |
| 列表滚动 | 保持流畅，不创建全部列表项 | P0 |
| 后台任务 | 不阻塞 UI 线程 | P0 |
| 长时间运行 | 不出现持续性内存增长 | P0 |
| 批量操作 | 避免逐条触发全量刷新 | P0 |

说明：

- CPU 的 0% 是空闲状态的目标，而非保证操作系统始终报告绝对 0%。
- 500 MB 主要针对完成初始化后的空闲状态。
- 工作集、私有内存和托管堆必须分别记录，不能仅以其中一个指标判断内存是否达标。
- 大规模导入、部署、清理等任务期间允许合理的短暂资源峰值。
- 不允许通过频繁强制 GC、隐藏真实任务或牺牲交互流畅度来制造虚假的性能达标结果。

## 1.3 开发原则

### UI 架构

- 保留现有 Avalonia 技术体系。
- 不迁移到 WebView、浏览器页面或其他 UI 技术。
- 继续采用 MVVM。
- 优先复用现有 ViewModel、服务接口和业务模型。
- UI 不直接访问 SQLite、文件系统或底层部署实现。
- 不在 View 中编写复杂业务逻辑。
- 不在 ViewModel 中直接操作控件。
- 所有耗时操作通过异步服务执行。
- 页面生命周期与数据生命周期分离。

### 性能

- 优先使用虚拟化列表。
- 避免重复加载和全量刷新。
- 避免高频轮询。
- 避免无意义的定时器和持续动画。
- 限制缓存容量。
- 避免长时间持有不再使用的 ViewModel。
- 所有后台任务都必须有明确的生命周期。
- 所有大批量操作都必须考虑取消、错误恢复和 UI 响应。

### 兼容性

- 仅面向 Windows 桌面环境。
- 不改变现有模组数据格式。
- 不破坏已有配置文件数据。
- 不擅自改变现有部署规则。
- 保留现有部署方式：文件复制、符号链接、硬链接。
- 保留 HD2 特有的 `.patch_*`、`.gpu_resources`、`.stream` 文件处理规则。
- 如果现有接口不能满足 UI 需求，应优先扩展接口，而不是在 UI 中绕过后端。

# 二、整体 UI 架构

## 2.1 主窗口布局

采用顶部主导航、页面工具栏、中央内容区和底部状态栏的桌面应用布局。

整体结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ HD2Mimnt       游戏状态             任务中心    通知    设置  │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  模组库       配置文件       设置       更多                  │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  当前页面标题                       页面专属操作              │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  页面工具栏                                                   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                                                              │
│                    页面主体内容                               │
│                                                              │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 当前配置：默认配置       部署状态：已同步          空闲        │
└──────────────────────────────────────────────────────────────┘
```

实际实现时，标题栏与导航栏可根据现有窗口装饰方式合并，但不得影响窗口拖动、缩放、最大化和关闭等系统功能。

## 2.2 主窗口区域

### A. 顶部标题栏

包含：

- HD2Mimnt 图标。
- 软件名称。
- 当前游戏识别状态。
- 全局任务中心入口。
- 通知入口。
- 设置快捷入口。
- 窗口控制按钮。

游戏状态至少包括：

- 已识别游戏。
- 未找到游戏。
- 路径无效。
- 正在检测。
- 游戏文件状态异常。

要求：

- 状态变化时进行增量更新。
- 不得为了显示游戏状态而持续扫描整个游戏目录。
- 游戏目录检测应由专门服务负责。
- 未检测到游戏时，不阻塞软件其他页面的使用。
- 不允许在每次页面切换时重新执行完整的游戏目录检测。

### B. 顶部主导航

固定提供以下一级页面：

1. 模组库
2. 配置文件
3. 设置
4. 更多

导航采用顶部横向排列。

要求：

- 当前页面具有清晰的选中状态。
- 页面切换不应重复创建所有页面。
- 页面切换不应触发全量模组扫描。
- 页面切换不应触发全量数据库查询。
- 页面切换时保留合理的临时状态。
- 页面不可见时，暂停不必要的 UI 更新和动画。
- 允许窗口缩小时调整导航间距，但不得让主要导航消失。

任务中心不占用一级导航位置。

### C. 页面标题与工具栏

每个一级页面拥有独立标题和操作区域。

页面工具栏根据当前页面动态显示。

模组库工具栏：

- 搜索。
- 分类筛选。
- 状态筛选。
- 排序。
- 导入模组。
- 新建或添加模组入口。

配置文件工具栏：

- 搜索配置文件。
- 新建配置文件。
- 排序。
- 配置文件管理操作。

设置工具栏：

- 设置分类导航。
- 设置搜索。
- 恢复默认设置入口。

更多页面：

- 根据具体功能提供对应工具栏。

### D. 主内容区域

负责显示当前一级页面。

要求：

- 页面内容不得与全局导航耦合。
- 不允许直接在 MainWindow 中堆积全部业务页面。
- 页面内容通过独立 View 与 ViewModel 实现。
- 页面切换不得导致整个应用重新初始化。
- 页面应支持合理的最小尺寸。
- 页面在高 DPI 和不同窗口大小下正常布局。
- 避免固定宽度导致大量留白或内容溢出。

### E. 底部状态栏

显示：

- 当前配置文件。
- 当前部署状态。
- 后台任务运行状态。
- 必要的错误或警告状态。

状态示例：

```text
当前配置：默认配置
部署状态：已同步
后台任务：空闲
```

状态栏不显示不必要的实时性能数字，避免持续刷新。

点击部署状态可以打开部署详情；点击后台任务状态可以打开任务中心。

## 2.3 主窗口响应式布局

支持以下窗口状态：

- 正常窗口。
- 最大化窗口。
- 较窄窗口。
- 高 DPI 显示环境。

要求：

- 不能依赖固定像素尺寸构建整个界面。
- 核心操作始终可见。
- 窄窗口优先收起辅助区域。
- 侧边栏和详情面板应支持折叠。
- 不允许因为窗口缩小而遮挡主要按钮。
- 不应使用过度复杂的动态布局造成不必要的布局计算。

# 三、页面一：模组库

优先级：P0

模组库是 HD2Mimnt 的核心页面，必须优先完成。

## 3.1 页面目标

实现高效的大规模模组管理。

用户应能在一个主要页面中完成绝大部分模组管理操作，而不需要频繁打开多个页面。

支持：

- 模组浏览。
- 模组搜索。
- 分类筛选。
- 状态筛选。
- 排序。
- 单个模组操作。
- 多模组批量操作。
- 模组详情。
- 模组导入。
- 模组删除。
- 部署。
- 清理。

## 3.2 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 模组库                                      添加模组  更多操作 │
├──────────────────────────────────────────────────────────────┤
│ 全部模组    已启用    未启用    已部署    存在冲突             │
├──────────────────────────────────────────────────────────────┤
│ 搜索模组名称……       分类       状态       排序               │
├──────────────────────────────────────────────────────────────┤
│ □ 全选当前筛选结果                       共 1,284 个模组       │
├──────────────────────────────────────────────────────────────┤
│ □ [图标] 高清护甲材质                已启用   已部署     ⋮    │
│ □ [图标] 武器模型替换                已启用   已部署     ⋮    │
│ □ [图标] 环境音效优化                未启用   未部署     ⋮    │
│ □ [图标] UI 优化                     已启用   未部署     ⋮    │
│                                                              │
│                 虚拟化模组列表                               │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 已选择 0 个模组                 启用  禁用  删除  部署         │
└──────────────────────────────────────────────────────────────┘
```

布局分为：

1. 页面标题区域。
2. 统计与状态筛选区域。
3. 搜索和筛选工具栏。
4. 模组列表。
5. 条件显示的批量操作栏。
6. 可选的模组详情面板。

## 3.3 模组列表

每个模组列表项应包含：

- 选择框。
- 模组图标或缩略图。
- 模组名称。
- 模组分类。
- 模组版本。
- 当前配置中的启用状态。
- 当前部署状态。
- 更多操作菜单。

允许根据窗口宽度隐藏次要信息，但不能隐藏影响核心操作的状态。

### 列表要求

- 使用虚拟化列表。
- 不得为全部模组创建常驻 UI 控件。
- 支持 10,000+ 条模组数据。
- 支持滚动时增量加载。
- 支持快速跳转到筛选结果。
- 支持键盘导航。
- 支持多选。
- 支持合理的列表项高度。
- 支持空列表状态。
- 支持加载失败状态。
- 支持模组图标缺失时的默认占位图。
- 不允许因为某个模组图标加载失败而影响整个列表。

### 虚拟化要求

仅创建当前可视区域及少量缓冲区域中的列表项。

滚动时：

- 复用列表项。
- 避免重复创建和销毁大量控件。
- 避免每次滚动重新查询数据库。
- 避免在 UI 线程执行图片解码。
- 避免因列表项高度频繁变化而导致滚动位置跳动。

当数据源发生变化时，只更新受到影响的列表项。

## 3.4 模组搜索

搜索范围：

- 模组名称。
- 模组标识符。
- 模组描述（如果已有相关数据）。
- 模组分类。
- 后端已有的其他可搜索字段。

要求：

- 支持实时搜索。
- 支持大小写不敏感搜索。
- 支持清空搜索。
- 支持搜索与筛选组合。
- 支持搜索结果数量显示。
- 不得每输入一个字符就触发完整数据库扫描。
- 对高频输入采用适当的防抖机制。
- 搜索结果应保持稳定，不应因后台无关状态变化而跳动。

性能目标：

- 常见数据集下，搜索结果更新目标不超过 100 ms。
- 对 10,000 条模组数据进行专项测试。
- 不允许搜索期间阻塞 UI 线程。

## 3.5 模组筛选

至少支持：

- 全部。
- 已启用。
- 未启用。
- 已部署。
- 未部署。
- 存在冲突（仅当后端具备可靠的冲突检测能力时显示）。

分类筛选应复用现有模组分类模型。

要求：

- 可组合多个筛选条件。
- 支持一键清除筛选。
- 显示当前生效的筛选条件。
- 不允许筛选操作触发全量模组对象重建。
- 筛选结果与批量选择状态保持一致。

对于尚未实现或无法可靠计算的筛选条件，不得伪造结果。

## 3.6 模组排序

支持的排序方式：

- 名称升序。
- 名称降序。
- 添加时间。
- 最近修改时间（存在可靠数据时）。
- 分类。
- 部署状态。

要求：

- 排序不改变模组本身的持久化顺序，除非用户明确要求。
- 排序结果必须稳定。
- 相同排序键应使用稳定的次级排序键。
- 不得每次排序都重新加载全部模组详情。
- 大型列表的排序操作不得阻塞 UI 线程。

## 3.7 模组选择

支持：

- 单个选择。
- 多个连续选择。
- Ctrl 多选。
- Shift 范围选择。
- 全选当前筛选结果。
- 取消全部选择。

要求：

- 选择状态与模组数据分离。
- 搜索、筛选、排序时合理保留选择。
- 全选默认只选择当前筛选结果。
- 全选不得意外选中被隐藏的全部模组。
- 批量操作开始后锁定必要的操作上下文，避免目标发生变化。
- 模组被删除后及时清理对应选择状态。

## 3.8 模组启用与禁用

单个操作：

- 启用模组。
- 禁用模组。

批量操作：

- 批量启用。
- 批量禁用。

要求：

- 操作优先修改当前配置文件中的模组状态。
- 使用现有配置文件服务。
- 不得在 UI 层直接修改数据库。
- 不得将启用状态错误地等同于已部署状态。
- 操作成功后进行局部更新。
- 批量操作使用一次合理的业务提交，避免逐条提交导致反复刷新。
- 批量操作失败时明确指出失败对象。
- 对不支持的状态转换给出清晰提示。

## 3.9 模组详情面板

点击模组后，可以打开详情面板。

详情至少包括：

- 名称。
- 标识符。
- 版本。
- 分类。
- 描述。
- 模组源文件位置（已有相关信息时）。
- 部署状态。
- 当前配置中的启用状态。
- 文件清单。
- 相关配置文件信息（仅在有可靠数据时）。

支持：

- 启用或禁用。
- 删除。
- 查看文件。
- 查看部署详情。

要求：

- 详情面板按需创建。
- 关闭详情后解除不必要的对象引用。
- 切换选中项时仅更新详情数据。
- 不得因为打开详情而重新扫描全部模组。
- 大型文件清单采用虚拟化或分页方式。
- 详情中的文件路径应支持复制。

## 3.10 添加和导入模组

导入入口应支持现有后端已经支持的来源和格式。

实现步骤：

1. 用户选择导入来源。
2. UI 调用现有导入服务。
3. 后台执行文件读取、解析和校验。
4. 向任务中心报告进度。
5. 导入成功后更新模组库。
6. 失败时显示可理解的错误信息。

要求：

- 文件读取不在 UI 线程执行。
- 大型导入支持取消。
- 导入过程中保留已有列表的可操作性。
- 导入完成后只刷新新增或发生变化的模组。
- 不得为显示导入进度而持续扫描文件。
- 对重复模组采用现有后端规则处理。
- 不得在 UI 层自行猜测或覆盖模组格式。

## 3.11 删除模组

删除操作必须与现有后端删除规则保持一致。

删除前显示影响范围：

- 将删除的模组。
- 受影响的配置文件。
- 相关的已部署文件。
- 是否涉及其他依赖对象（仅在后端支持检测时）。

执行要求：

1. 显示确认对话框。
2. 获取后端的删除影响信息。
3. 用户确认后调用现有删除服务。
4. 后台执行实际删除。
5. 成功后同步更新模组库和配置文件页面。
6. 失败时保留准确的状态并显示错误。

特别要求：

- 模组库删除模组时，相关配置文件记录必须按既定规则一并清理。
- 已部署文件必须由现有清理和删除逻辑负责处理。
- 不得在 UI 中自行递归删除游戏目录文件。
- 不得先从 UI 中永久移除数据，再假定后端删除一定成功。
- 删除过程中禁止对同一目标执行相互冲突的操作。

## 3.12 部署与清理

部署和清理是同一套核心工作流的重要组成部分。

UI 必须提供：

- 部署。
- 清理已部署模组。
- 查看当前部署状态。
- 查看部署差异（如果后端支持）。
- 查看任务进度。
- 查看失败详情。

### 部署流程

```text
用户发起部署
      |
      v
检查当前配置与部署状态
      |
      v
提交后端部署任务
      |
      v
后台执行文件操作
      |
      +----> 更新任务进度
      |
      v
任务完成或失败
      |
      v
刷新相关状态
      |
      v
显示最终结果
```

### 清理流程

```text
用户发起清理
      |
      v
获取清理范围与影响
      |
      v
用户确认
      |
      v
提交后端清理任务
      |
      v
后台清理已部署文件
      |
      +----> 更新任务进度
      |
      v
任务完成或失败
      |
      v
刷新部署状态
```

部署方式：

- 文件复制。
- 符号链接。
- 硬链接。

UI 负责显示和选择部署方式，具体实现由后端完成。

要求：

- 不允许 UI 自行实现文件复制、链接创建或删除。
- 部署和清理必须使用现有服务。
- 部署期间 UI 保持响应。
- 部署任务应有明确的进度和结果。
- 同一目标上的冲突部署操作必须被协调。
- 取消操作必须遵循后端支持的安全取消边界。
- 不允许在文件操作尚未结束时错误地显示任务成功。
- 清理后应重新获取可靠的部署状态。

# 四、页面二：配置文件

优先级：P0

## 4.1 页面目标

为用户提供完整的配置文件管理功能。

配置文件用于记录不同的模组组合及其状态。

配置文件切换不能导致模组库重复加载，也不能导致 UI 卡顿。

## 4.2 页面布局


## 4.3 配置文件列表

每个配置文件显示：

- 名称。
- 描述（如已有字段）。
- 模组数量。
- 当前配置标识。
- 最后修改时间（如已有可靠数据）。
- 操作菜单。

操作：

- 切换。
- 编辑。
- 复制。
- 重命名。
- 删除。

要求：

- 当前配置有清晰标识。
- 配置文件数量较大时支持搜索。
- 不允许每次打开页面都重新解析全部配置文件。
- 删除当前配置前必须有明确的后续处理规则。
- 不允许 UI 层擅自决定数据库中的默认配置。

## 4.4 新建配置文件

提供独立的新建流程。

支持：

- 空白配置。
- 复制现有配置。

如果现有后端支持其他创建方式，可在确认数据模型后扩展。

新建流程：

1. 输入配置文件名称。
2. 选择创建方式。
3. 如果选择复制，指定来源配置文件。
4. 调用配置文件服务。
5. 显示创建结果。
6. 更新配置文件列表。

要求：

- 名称校验复用后端规则。
- 不得在 UI 层独立制定与后端冲突的命名规则。
- 创建失败时保留用户输入。
- 创建成功后不强制部署，除非用户明确选择。
- 不允许因为创建配置文件而复制全部模组源文件。

## 4.5 配置文件切换

切换配置文件必须区分两个概念：

1. 当前正在编辑和使用的逻辑配置。
2. 游戏目录中实际已经部署的文件状态。

切换流程：

```text
用户选择目标配置
        |
        v
检查当前配置是否存在未保存更改
        |
        +----> 有未保存更改：提示处理
        |
        v
切换逻辑配置
        |
        v
更新当前配置状态
        |
        v
刷新必要的 UI 状态
        |
        v
根据部署状态决定是否需要部署
```

要求：

- 切换逻辑配置与实际部署分离。
- 仅切换逻辑配置时，不得无条件重做所有文件操作。
- 已缓存的配置切换应快速完成。
- 目标配置的必要数据按需读取。
- 通过版本号或请求标识避免旧请求覆盖新配置。
- 连续切换配置时，必须避免状态竞争。
- 如果目标配置正在被其他任务修改，应根据后端规则协调。
- 切换完成后，模组库应立即显示新配置对应的启用状态。

## 4.6 配置文件详情

详情显示：

- 配置文件名称。
- 模组总数。
- 已启用模组数。
- 未启用模组数。
- 模组列表。
- 当前部署状态。

支持：

- 搜索模组。
- 筛选模组。
- 启用和禁用。
- 批量启用和禁用。
- 复制配置文件。
- 与其他配置文件比较。

模组列表应复用模组库的列表组件和虚拟化机制。

不得为了配置文件详情再创建一套独立的大型模组列表实现。

## 4.7 配置文件对比

优先级：P1

比较两个配置文件的差异。

显示：

- 两边共有的模组。
- 仅存在于左侧的模组。
- 仅存在于右侧的模组。
- 双方都存在但启用状态不同的模组。

要求：

- 只比较现有模型可以可靠提供的数据。
- 不得将模组版本不同误判为模组本身不同。
- 支持按差异类型筛选。
- 大量差异使用虚拟化列表。
- 对比结果不得直接修改配置文件。
- 如需同步差异，必须经过明确的用户操作。

## 4.8 删除配置文件

要求：

- 删除前确认。
- 当前配置删除时，遵循现有后端定义的安全规则。
- 不得擅自删除模组库中的模组。
- 不得擅自清理仍被其他配置使用的模组。
- 删除成功后刷新配置文件列表。
- 删除失败时保留原有状态。

# 五、页面三：设置

优先级：P0

## 5.1 页面目标

统一管理软件运行所需的配置。

采用分类式设置页面，不将所有设置堆在一个长页面中。

## 5.2 设置分类

### A. 游戏设置

- 游戏安装目录。
- 自动识别状态。
- 手动指定游戏目录。
- 路径有效性检测。
- 游戏版本或必要文件检测（后端支持时）。

要求：

- 路径检测通过现有服务完成。
- 不在 UI 线程执行目录扫描。
- 不允许反复自动扫描整个游戏目录。
- 路径无效时给出具体原因。

### B. 部署设置

- 默认部署方式。
- 默认部署行为。
- 部署前检查选项（以后端现有能力为准）。
- 清理相关设置（以后端现有能力为准）。

部署方式：

- Copy。
- Symbolic Link。
- Hard Link。

要求：

- 展示每种部署方式的名称和说明。
- 不允许 UI 伪造不受后端支持的部署选项。
- 更改默认部署方式不应自动触发文件操作。
- 不允许因修改设置而破坏已经部署的文件。

### C. 模组库设置

- 默认排序方式。
- 默认筛选条件。
- 列表展示密度。
- 是否显示模组缩略图。
- 其他现有模组库偏好。

要求：

- UI 偏好与模组业务数据分离。
- 更改显示偏好不触发模组数据全量重载。
- 不支持的偏好不提前暴露。

### D. 外观设置

- 深色主题。
- 浅色主题。
- 跟随系统（如果当前主题实现支持）。
- 界面缩放或密度（视 Avalonia 当前实现能力而定）。
- 动画偏好（如果实际提供该设置）。

要求：

- 主题切换应尽量即时生效。
- 不允许主题切换重新初始化全部页面。
- 主题设置应持久化。
- 不允许使用大量重复的主题资源实例。

### E. 性能与缓存

- 当前缓存状态。
- 缓存占用信息。
- 清理可安全清理的缓存。
- 诊断信息入口。
- 性能日志开关（仅在有实际实现时显示）。

要求：

- 缓存清理不能删除用户模组源文件。
- 缓存清理不能擅自删除部署文件。
- 缓存占用统计不得依靠高频全盘扫描。
- 性能日志默认关闭或采用低开销策略。

### F. 高级设置

只放置确实需要向用户开放的高级选项。

不得把内部调试开关、未经验证的性能参数直接暴露给普通用户。

## 5.3 设置持久化

要求：

- 复用现有设置存储。
- 避免重复实现设置数据库。
- 设置变更与页面状态保持同步。
- 设置保存失败时提供错误提示。
- 对重要设置提供恢复默认值入口。
- 不允许设置页面关闭后仍保留无意义的后台订阅。

# 六、页面四：更多

优先级：P1

## 6.1 页面目标

收纳非核心、低频但具有实际用途的功能。

不让低频工具挤占模组库和配置文件的主要操作空间。

## 6.2 功能规划

### A. 外部工具

显示项目已经集成或实际支持的外部工具。

包括：

- 工具名称。
- 工具状态。
- 启动入口。
- 必要的路径配置。
- 运行结果或错误信息。

要求：

- 外部工具由现有服务管理。
- UI 不得直接拼接未经校验的命令行参数。
- 不允许启动工具时阻塞 UI。
- 不允许把尚未实现的工具显示为已可用。

### B. 数据备份与恢复

优先级：P1

如果现有后端具备对应能力，则提供：

- 创建备份。
- 查看备份列表。
- 恢复备份。
- 删除备份。
- 显示备份时间和内容。

备份操作必须与模组部署操作区分。

恢复前应明确提示影响范围。

### C. 日志与诊断

提供：

- 查看应用日志。
- 查看最近的错误。
- 复制诊断信息。
- 导出日志（如果现有服务支持）。

要求：

- 大型日志采用虚拟化或分页。
- 日志读取不阻塞 UI。
- 不将日志持续加载到内存。
- 避免 UI 自身的日志展示产生大量重复对象。

### D. 关于

显示：

- 软件名称。
- 软件版本。
- 构建版本（如果已有）。
- 项目地址。
- 许可证信息。
- 第三方组件声明。

不得在此处展示不准确的版本或未经核实的项目地址。

# 七、全局任务中心

优先级：P0

## 7.1 任务中心定位

任务中心是全局功能，不属于某个单独页面。

统一管理所有需要异步执行、显示进度或报告结果的任务。

任务类型至少包括：

- 模组导入。
- 模组扫描。
- 部署。
- 清理。
- 配置文件相关的耗时操作。
- 备份与恢复（如果实现）。
- 其他后端已有的耗时操作。

## 7.2 任务中心入口

入口位于顶部标题栏。

显示：

- 是否存在运行中的任务。
- 是否存在未查看的错误。
- 必要的任务数量。

不允许为显示任务状态而每隔极短时间刷新整个界面。

优先采用后端事件、消息通知或现有任务状态变更机制。

## 7.3 任务状态

统一任务状态：

- Pending：等待执行。
- Running：正在执行。
- Completed：已完成。
- Failed：执行失败。
- Cancelled：已取消。

如果现有任务模型已经定义其他状态，应优先兼容已有模型。

## 7.4 任务详情

每个任务显示：

- 任务名称。
- 任务类型。
- 当前状态。
- 开始时间。
- 已用时间。
- 进度。
- 当前处理对象（如果有）。
- 结果摘要。
- 错误信息。

进度未知时使用不确定进度指示器，不得伪造百分比。

## 7.5 任务取消

要求：

- 只有支持安全取消的任务才显示取消按钮。
- 取消后等待后端确认最终状态。
- 不得在用户点击取消时立即伪造任务已取消。
- 已经进入不可安全中断阶段的操作，应明确告知用户。
- 取消失败时保留真实任务状态。

## 7.6 任务并发控制

要求：

- 同一部署目标上的冲突任务不能同时执行。
- 相同目标的重复部署请求应进行合理协调。
- 不同类型的任务根据现有后端安全规则确定并发策略。
- 任务中心不应成为新的业务调度实现。
- UI 负责提交、显示和取消请求，调度由后端完成。

# 八、全局通知系统

优先级：P0

## 8.1 通知类型

至少包括：

- 成功。
- 警告。
- 错误。
- 普通信息。

典型通知：

- 模组导入完成。
- 部署成功。
- 清理完成。
- 配置文件切换成功。
- 操作失败。
- 游戏路径无效。
- 存在需要用户处理的问题。

## 8.2 通知行为

要求：

- 普通通知可以自动消失。
- 重要错误应保留，直到用户查看或主动关闭。
- 通知应提供跳转到相关页面的入口。
- 多条相同通知应适当合并。
- 不允许高频弹窗阻碍正常操作。
- 后台任务完成通知应与任务中心状态一致。

通知系统应统一实现，不允许每个页面独立创建一套通知逻辑。

# 九、统一交互规范

优先级：P0

## 9.1 操作反馈

所有用户操作必须有明确反馈。

包括：

- 点击反馈。
- 加载反馈。
- 成功反馈。
- 失败反馈。
- 禁用状态。
- 操作冲突提示。

对于快速完成的操作，不必强制显示加载动画。

对于耗时任务，显示任务状态而不是长时间阻塞式弹窗。

## 9.2 危险操作

以下操作需要明确的确认机制：

- 删除模组。
- 删除配置文件。
- 清理已部署文件。
- 恢复备份。
- 其他不可逆或可能影响大量文件的操作。

确认对话框必须说明具体影响。

不应对普通启用、禁用和页面切换等低风险操作反复弹出确认框。

## 9.3 键盘操作

核心页面至少支持：

- Ctrl + F：搜索。
- Esc：关闭当前弹窗或取消临时选择。
- Enter：确认当前可确认操作。
- Delete：在符合条件时发起删除确认。
- Ctrl + A：在模组列表中全选当前筛选结果。
- 方向键：在支持键盘导航的列表中移动焦点。

快捷键不得覆盖文本框中原有的编辑行为。

## 9.4 空状态

每个主要页面都必须提供空状态。

例如：

- 尚未导入任何模组。
- 没有配置文件。
- 搜索无结果。
- 当前筛选无匹配项。
- 暂无后台任务。
- 暂无日志。

空状态应提供明确的下一步操作，而不是只显示空白区域。

## 9.5 错误状态

错误提示应尽量包含：

- 操作名称。
- 错误原因。
- 是否影响现有数据。
- 是否可以重试。
- 需要用户采取的下一步操作。

内部异常详情可以写入日志，但不应把大段堆栈直接展示给普通用户。

# 十、UI 与后端的职责划分

优先级：P0

## 10.1 UI 层职责

UI 层负责：

- 页面展示。
- 用户输入。
- 页面导航。
- 数据绑定。
- 临时交互状态。
- 操作请求。
- 异步任务进度展示。
- 任务结果展示。
- 错误反馈。

UI 不负责：

- 直接操作文件系统。
- 直接执行部署。
- 直接执行清理。
- 直接修改 SQLite。
- 自行解析全部模组文件。
- 自行决定配置文件持久化规则。
- 自行处理硬链接、符号链接及复制实现。
- 自行实现模组删除的级联清理。

## 10.2 ViewModel 职责

ViewModel 负责：

- 暴露页面所需的数据。
- 管理页面临时状态。
- 处理用户命令。
- 调用现有业务服务。
- 管理异步请求的生命周期。
- 对 UI 进行增量通知。
- 防止过期异步结果覆盖新状态。

ViewModel 不负责：

- 直接调用文件 API 执行部署。
- 直接操作数据库。
- 承担长期运行的后台轮询。
- 实现与业务服务重复的完整业务逻辑。

## 10.3 服务层职责

复用现有后端服务。

如果现有服务缺少 UI 所需的功能，优先扩展已有接口。

可能需要的服务接口：

- 模组查询服务。
- 配置文件服务。
- 部署服务。
- 清理服务。
- 导入服务。
- 游戏路径服务。
- 任务状态服务。
- 设置服务。
- 通知服务。

以上名称仅表示职责，不要求为了命名一致而重复创建已有服务。

## 10.4 数据流

推荐数据流：

```text
用户操作
   |
   v
View
   |
   v
ViewModel
   |
   v
现有业务服务
   |
   v
后端处理
   |
   v
返回结果或状态事件
   |
   v
ViewModel 增量更新
   |
   v
View 数据绑定更新
```

要求：

- 不允许 View 直接访问数据库。
- 不允许 View 绕过 ViewModel 调用部署服务。
- 不允许多个 ViewModel 为同一数据维护互相冲突的独立状态。
- 全局任务状态应由统一的任务管理机制提供。
- 对于异步操作，必须正确处理页面关闭、请求取消和对象释放。

# 十一、性能优化专项

优先级：P0

## 11.1 CPU 优化

### 空闲状态

空闲状态定义：

- 没有正在执行的用户任务。
- 没有正在执行的必要后台扫描。
- 没有需要立即处理的文件事件。
- 没有需要执行的数据库写入。

要求：

- 禁止无意义的高频轮询。
- 禁止持续执行全量模组刷新。
- 禁止无意义的定时排序。
- 禁止后台反复计算模组统计信息。
- 禁止不可见页面持续执行不必要的更新。
- 禁止空闲时反复重新检测游戏目录。
- 禁止 UI 因动画或无意义状态刷新持续占用 CPU。

目标：

空闲时 CPU 应接近 0%，短暂系统波动可以接受，但不能存在持续性应用级计算。

### 搜索与筛选

要求：

- 避免每次输入都进行全量查询。
- 对搜索输入进行适当的防抖。
- 对简单筛选优先使用内存中已有的轻量数据。
- 对复杂查询使用后端已有的查询能力。
- 不允许在 UI 线程进行大规模排序。
- 避免重复计算相同的筛选结果。

### 数据更新

要求：

- 采用增量更新。
- 避免无关属性变化导致整个列表刷新。
- 避免频繁触发布局重算。
- 批量操作结束后统一提交必要的 UI 更新。
- 对短时间内连续到达的状态变化进行合理合并。

## 11.2 内存优化

### 目标

完成初始化后，在普通空闲使用场景下：

Working Set < 500 MB。

同时持续监控：

- Working Set。
- Private Bytes。
- Managed Heap。
- GC Heap Size。
- 缓存容量。

### 数据加载

要求：

- 模组列表只加载展示所需字段。
- 详情信息按需加载。
- 文件清单按需加载。
- 不允许启动时一次性读取所有大型文件。
- 不允许将整个游戏目录的文件清单长期保存在内存中。
- 对大型数据集使用分页、分批或虚拟化。
- 根据现有数据模型决定合理的缓存范围。

### 图片缓存

要求：

- 按需加载图片。
- 限制图片缓存容量。
- 避免重复解码相同图片。
- 图片解码不得阻塞 UI 线程。
- 不再使用的图片资源应允许释放。
- 缩略图尺寸应与实际显示尺寸匹配。
- 禁止为了缩略图缓存大量原始大图。

### ViewModel 生命周期

要求：

- 主窗口长期保留必要的全局状态。
- 页面 ViewModel 采用明确的生命周期策略。
- 关闭临时详情面板时解除无用引用。
- 关闭对话框后清理临时数据。
- 取消不再需要的异步请求。
- 解除不再需要的事件订阅。
- 不允许全局服务无期限持有所有历史页面对象。

### 缓存策略

每类缓存必须明确：

- 缓存内容。
- 缓存创建条件。
- 缓存容量。
- 缓存失效条件。
- 缓存清理时机。
- 是否允许持久化。

不允许创建没有容量限制、没有失效条件的全局缓存。

### 垃圾回收

要求：

- 优先解决真实的对象生命周期问题。
- 不通过频繁调用 GC 来降低表面内存。
- 不在普通页面切换后无条件执行完整垃圾回收。
- 不以强制 GC 代替缓存管理。
- 通过内存快照和分配分析定位真实问题。

## 11.3 UI 渲染优化

要求：

- 模组列表必须虚拟化。
- 大型选择器必须虚拟化。
- 避免深层嵌套布局。
- 避免不必要的阴影、模糊和复杂透明效果。
- 避免大量持续动画。
- 避免列表项中存在高成本转换器。
- 避免重复创建相同的图标和装饰资源。
- 对复杂详情使用按需加载。
- 尽量避免频繁改变列表项高度。

## 11.4 后台任务优化

要求：

- 所有耗时任务使用异步流程。
- UI 线程不得执行大规模文件 I/O。
- UI 线程不得执行长时间数据库查询。
- 任务进度更新应进行合理节流。
- 不允许每处理一个文件就强制刷新整个页面。
- 任务结束后统一提交必要的状态变化。
- 任务失败时正确释放资源。
- 任务取消时正确释放资源。
- 对无法取消的安全临界阶段提供明确状态。

# 十二、数据与状态一致性

优先级：P0

## 12.1 模组状态

需要明确区分：

- 模组是否存在于模组库。
- 模组是否在当前配置文件中启用。
- 模组是否已经部署。
- 模组部署是否与当前配置一致。

不得将上述状态合并为一个简单的启用开关。

## 12.2 配置文件状态

需要明确区分：

- 当前选中的配置文件。
- 正在编辑的配置文件。
- 尚未保存的修改。
- 实际部署所使用的配置。
- 部署结果是否与目标配置一致。

## 12.3 异步请求竞争

重点处理：

- 连续切换配置文件。
- 搜索过程中切换页面。
- 部署过程中修改配置。
- 删除模组时打开详情。
- 后台导入与列表筛选同时发生。

要求：

- 每个异步操作具有明确的目标上下文。
- 过期请求不能覆盖最新状态。
- 必要时使用取消令牌。
- 对无法取消的后端任务使用状态协调。
- 不允许 UI 显示与后端实际结果矛盾的状态。

## 12.4 刷新策略

采用按需刷新。

以下情况可以触发局部刷新：

- 新增模组。
- 删除模组。
- 修改模组启用状态。
- 配置文件切换。
- 部署完成。
- 清理完成。

不允许每次操作都重新加载整个模组库、全部配置文件及所有详情。

# 十六、性能测试计划

## 16.1 测试环境

所有性能测试必须记录：

- Windows 版本。
- .NET 运行时版本。
- 应用构建配置。
- CPU 型号。
- 内存容量。
- 屏幕分辨率。
- DPI 缩放比例。
- 模组数据规模。
- 测试持续时间。

优先使用 Release 构建进行性能验收。

Debug 构建只用于功能开发和调试，不作为最终性能指标依据。

## 16.2 CPU 测试

测试场景：

| 场景 | 测试内容 |
|---|---|
| 启动完成 | 测量初始化后的 CPU |
| 空闲 5 分钟 | 记录持续 CPU 占用 |
| 空闲 30 分钟 | 检查是否存在后台循环 |
| 切换页面 | 检查布局与状态更新 |
| 搜索模组 | 检查搜索开销 |
| 筛选模组 | 检查筛选开销 |
| 批量操作 | 检查重复刷新 |
| 任务中心 | 检查状态更新开销 |
| 长时间运行 | 检查后台无效活动 |

验收原则：

- 空闲阶段不应存在持续性 CPU 消耗。
- 普通交互允许短暂 CPU 峰值。
- 搜索、筛选和切换页面不应造成长时间高 CPU 占用。
- 任务进度更新不能导致持续的高频渲染。

## 16.3 内存测试

测试场景：

| 场景 | 测试内容 |
|---|---|
| 启动完成 | 基础内存占用 |
| 空闲 5 分钟 | Working Set 与 Private Bytes |
| 空闲 30 分钟 | 内存稳定性 |
| 打开模组库 | 列表内存开销 |
| 加载 10,000 个模组 | 大规模数据开销 |
| 打开详情 | 详情面板开销 |
| 连续切换页面 | 页面生命周期 |
| 连续切换配置 | 缓存增长 |
| 大规模导入 | 峰值内存 |
| 部署与清理 | 后台任务内存 |
| 长时间运行 | 是否存在内存泄漏 |

验收原则：

- 空闲 Working Set < 500 MB。
- 记录 Private Bytes，避免只关注工作集。
- 大规模任务允许合理峰值。
- 返回空闲状态后，内存应逐步趋于稳定。
- 不允许每次操作都导致永久性内存增长。

## 16.4 交互响应测试

建议采用以下目标：

| 操作 | 目标 |
|---|---:|
| 普通按钮反馈 | ≤ 100 ms |
| 搜索结果更新 | ≤ 100 ms |
| 常见筛选结果更新 | ≤ 100 ms |
| 已缓存配置的 UI 切换 | ≤ 100 ms |
| 页面导航反馈 | ≤ 100 ms |
| 批量操作界面反馈 | ≤ 100 ms |
| 大型部署任务 | 异步执行，不阻塞 UI |

响应时间的统计方式必须统一。

普通交互的响应时间主要衡量 UI 反馈，而不是整个文件操作完成时间。

## 16.5 大规模数据测试

至少测试：

- 1,000 个模组。
- 5,000 个模组。
- 10,000 个模组。

大型选择器至少测试：

- 1,000 条数据。
- 4,000 条数据。
- 8,000 条数据。

检查：

- 初次加载。
- 搜索。
- 筛选。
- 排序。
- 滚动。
- 多选。
- 批量操作。
- 内存增长。
- UI 线程阻塞。

不允许仅用少量测试数据证明虚拟化和性能达标。

# 十七、异常处理与恢复

优先级：P0

## 17.1 服务调用失败

所有服务调用都必须考虑：

- 返回失败。
- 抛出异常。
- 任务取消。
- 数据变化。
- 文件占用。
- 权限不足。
- 目标文件不存在。
- 目标文件状态与预期不一致。

要求：

- UI 不得因单个请求失败而崩溃。
- 失败后恢复合理的按钮状态。
- 不允许显示虚假的成功结果。
- 错误信息应具有可读性。
- 必要时提供重试入口。

## 17.2 页面关闭

页面关闭或切换时：

- 取消不再需要的请求。
- 解除不再需要的订阅。
- 清理临时对象。
- 不得误取消仍需要运行的全局任务。
- 不得因页面关闭而破坏正在执行的部署。

## 17.3 应用关闭

退出时：

- 识别正在执行的任务。
- 对无法安全中断的任务进行明确提示。
- 按现有后端规则处理后台任务。
- 不得无条件终止正在进行的文件操作。
- 确保重要状态能够正确恢复。
