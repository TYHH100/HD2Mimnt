# 兼容性检查与修复

Application 入口为 `ModCompatibilityService`，DI 已注册。后端覆盖检查、计划、已知格式修复、伴随恢复、备份及批量操作；前端已接入模组库、配置页、详情和设置。启动扫描默认关闭，需在设置保存后开启；不会自动修复。检查模组库所有变体的合法主补丁，已有部署需要重新部署才使用修复内容。

检查摘要持久化在 SQLite `CompatibilityResults` 表（仓储 `CompatibilityResultRepository`）：按 ModId 覆盖写入状态、覆盖数、损坏标志、问题列表（封顶 8 条）与检查时的模组目录内容戳（`ModContentStamp`，文件数+总字节+最大 mtime）。每次检查自动落库；启动时无论是否开启启动扫描都先从持久化摘要回填角标，内容戳不匹配或模组已删除的行不回填，孤儿行在读取时清理。内容变更清空角标后也仅恢复未变化模组。

## 设置与游戏参考数据

- “设置 → 兼容性”提供“启动时检查模组兼容性”和“允许批量修复”，均默认关闭。保存到 SQLite 的 `Compatibility.CheckOnStartup` / `Compatibility.EnableBatchRepair`；可独立保存，不受游戏目录验证影响。此分类恢复默认只重置 `Compatibility.*`，不清除游戏路径或已构建数据。“入口自定义”使用稳定 ID `settings.compatibility` 控制分类显示。
- 启动检查在主窗口初始化完成、游戏路径应用后后台执行，不阻塞初始化、不自动弹窗；完成通知可打开结果。关闭启动检查取消正在执行的自动扫描，退出等待清理。批量修复开关即时控制按钮和执行入口，关闭时保留全库检查、批量预览和单个修复。启动检查按内容戳增量执行：未变化模组直接回填持久化摘要（其 CheckedAtUtc 保持原值），只重扫其余模组。
- “游戏参考数据 → 构建并保存 / 重新构建”从已经保存的游戏路径读取 DSAR，保存二进制索引到当前 `CachePath/compatibility/game-reference-index.bin`。界面显示构建时间、归档包数、Unit 数及保存位置，构建有进度和取消，退出等待操作结束。护甲名称另有手动在线更新按钮，继续复用已有的一天有效期与离线缓存机制。

- 过期以安装路径及 `bundles*.nxa` 的文件名、大小、UTC 修改/创建时间指纹和缓存格式版本判断，不按固定天数盲目重建。启动和进入兼容性设置时只自动更新已有的过期缓存；首次可手动构建，首次兼容性读取也按需构建。每次参考读取都校验指纹，过期自动重建。

### 实际 DSAR 大块读取修复（2026-10-18）

真实游戏的未压缩块可超过单次资源读取的 64 MiB 上限；本机 `bundles.08.nxa` 包含 898,521,500 字节块。原构造器错误地将此上限用于块表，导致“DSAR 块范围或顺序无效”。现将块表范围校验与资源/解码内存上限分开，未压缩块直接随机读取请求区间，磁盘缓存也支持大块描述；仍拒绝物理越界、重叠、尺寸不一致与未知压缩格式。错误信息补充文件名与块编号，仅出错时格式化。

实际安装目录只读构建验证成功：9,715 个包、7,912 个 Unit，单次约 3.56 秒，保存索引 18,333,283 字节；新读取器载入缓存并抽查 16 个 Unit 均为 Found，版本 10800438（0xA4CD36），约 0.60 秒。此时间为本机单次观测，不构成跨机器性能结论或游戏运行验证。测试补充 96 MiB 与 898,521,500 字节大块内随机读取和跨实例缓存复用，验证累计分配低于 16 MiB，避免整块载入；同时保留非法范围、块重叠与未压缩尺寸错误回归。

修复后 Release 构建成功，76 项兼容性相关单元测试和 1 项设置页实际构建 UI 测试通过。真实归档验证只读取游戏并写入本轮隔离目录；`.artifacts/dsar-smoke` 与 `.artifacts/dsar-fix` 中的验证源码、缓存和构建产物已于 2026-10-18 收尾时清理。

## 前端入口与操作

- 模组库侧栏检查全库；配置页侧栏检查正在查看配置的完整成员，包含折叠内容和锁定加载器；顶部批量工具栏仅检查所选模组。右键及详情按钮检查单个模组。分隔符不参与，Mod ID 去重。
- 两页与详情共用 ModCompatibilityViewModel 和全局浮窗，不增加导航页。左侧选择模组，右侧按检查结果、修复预览、备份管理分栏；长列表沿用 FluentAvalonia ListBox 虚拟化及不透明主题背景。
- 检查后，确定的模型版本不匹配或确定损坏（补丁结构不可读、必需伴随文件缺失）显示小扳手角标，位置紧邻冲突感叹号；悬停显示文案和最多三条问题，点击检查该模组，文案区分"模型版本不匹配"与"补丁损坏或缺少必需的伴随文件"。entry_index、GPU 采样等警告级诊断不上角标（2026-10-18 误报边界），只进详情。模组库和配置页同步显示同一结果；关闭浮窗或重建卡片保留会话结果，内容变更后清除并由持久化摘要按内容戳恢复未变化模组。未检查、版本匹配且结构完好、无需模型检测及检查错误不显示该角标，具体原因在检查详情中说明。
- 范围包含库内所有变体和未启用内容，并非仅当前配置选项的部署结果；版本判定只针对模型 Unit。Lua、骨骼、动画、音效等资源会在详情中说明但不参与模型版本结论，也不会生成模型修复动作。兼容、未确认、检测范围外与真实游戏验证的边界在检查页显示。
- 修复前先预览，可分别选择元数据、stream/GPU、Unit/Layout、材质和四种 LOD 策略。检查结果页另提供选中/全库一键修复：尚无计划时自动生成计划，再经同一数量确认执行；全库一键仍受批量修复设置门控，无可执行动作时明确提示。修复页的预览保留为计划详情视图。混合策略的 Unit 选择按模组独立保存；同一资源 ID 不会在不同模组间合并。更改选项立即使旧计划失效。
- 可修复计划经数量确认后执行；备份支持刷新、单文件恢复、时间点回滚、删除及每文件保留最近 3 份。修复与恢复后等待库列表、搜索索引和配置页刷新，保留 Mod/Profile 身份，提示重新部署。
- 检查、预览、修复及备份在后台运行。进度按批次限频回到 UI 线程；关闭和退出取消并等待清理。单项失败和恢复错误留在对应模组的操作详情，重新检查不会覆盖。
- 支持三语实时切换、深浅主题、960×600 窗口及报告复制。护甲名称按需从用户指定上游更新，离线保留哈希与可用缓存。

## 接口

| 调用 | 行为 |
| --- | --- |
| `CheckModAsync` / `CheckModsAsync` | TOC、载荷及伴随范围、Unit/LOD/Layout/GPU 检查；默认按 Game.Path 与游戏逐 ID 比较版本，批量合并参考请求 |
| `CreateRepairPlanAsync` / `RepairAsync` | 仅修元数据；预览包含位置、宽度、旧值、新值和阻止原因 |
| `CreateFullRepairPlanAsync` / `RepairFullAsync` | 恢复伴随、修元数据、迁移已知 Unit/材质；计划列出资源、LOD 策略、尺寸变化、警告及阻止原因 |
| `CreateCompanionRecoveryPlanAsync` / `RecoverCompanionsAsync` | 仅恢复缺失或范围不足的 stream/GPU |
| `CreateBatchRepairPlanAsync` / `RepairBatchAsync` | Mod ID 去重、顺序处理、逐项进度；单项文件错误继续，取消终止后续项；可传 perModOptions 保持逐模组 LOD 选择 |
| `GetBackupsAsync` / `GetBackupHistoryAsync` | 备份路径及 UTC、SHA-256、可恢复和当前内容匹配状态 |
| `RestoreBackupAsync` / `RollbackToAsync` | 恢复指定备份；或按每个原文件选择不晚于指定 UTC 的最新备份并统一恢复 |
| `DeleteBackupAsync` / `CleanOldBackupsAsync` | 删除当前模组备份及 sidecar；默认每个原文件保留 3 份 |
| `RefreshResourceNamesAsync` | 强制在线更新资源与归档名称，失败返回已有缓存及更新错误 |

`CompatibilityRepairOptions` 分别开关元数据、伴随恢复、Unit 修复和材质迁移。LOD 支持保留模组、使用游戏参考、自动、按 ID 混合，默认自动。耗时文件操作在后台执行并支持取消；前端通过 Application 服务调用。

## 判定与修复边界

TOC 使用 72 字节头、32 字节类型记录、80 字节资源记录；检查索引长度、条目序号、类型分布、资源范围和重叠，伴随逐条校验 offset/size。

元数据依据实际条目重建序号、类型计数及唯一连续类型组 ID。零 alignment 仅在同表有唯一合法非零参考时补足，全零保留未声明。Unit 尺寸修复要求 ending+8 恰好匹配下一载荷或文件末尾。无效主偏移仅从唯一等长物理空隙恢复；多个同尺寸空隙或多个资源竞争时拒绝。

Unit 深度检查包括内部尺寸、LOD、Legacy Layout 表、已知 StreamInfo/GPU 分量、stride、缓冲范围、有限顶点位置、权重和索引采样。GPU 使用局部随机读取；采样不等于完整网格验证。未知版本和分量保持未确认。修复复检只把结构类错误（内部尺寸、LOD、分量计数、步长、缓冲范围、GPU 载荷缺失）作为阻断条件；"GPU 采样"类启发式错误反映作者网格数据特征（GPU 载荷不被修复修改），只保留为诊断、不阻断修复，与检查判定边界一致——此前把任何深度错误当硬闸，曾把 135 个旧版 Unit 的旧角色材质包整体拒绝修复（2026-10-27 依据真实模组只读复现修正）。

现代 Unit 版本为 `0xA4CD36`，十进制即 `10800438`，不是两个版本。迁移只接受已知目标、可解析旧布局和有效结果，拒绝未知新版本降级。替换游戏 LOD 要求长度差 16 字节对齐，重定位后续 section 指针和 TOC 偏移，保留其他载荷及间隙。

自动策略仅迁移版本不匹配的 Unit，按各 Unit 的 mesh ID 差异或明显 GPU 扩展证据决定是否保留模组 LOD，不扩散到整包；版本已匹配时保留作者 LOD。该判断是启发式，可显式选择策略或指定 `PreserveModLodUnitIds`。已知旧角色材质包的 version 1 Unit 迁移强制用游戏 LOD，计划中给出说明。

材质只处理精确已知 schema：角色 parent `54AE9CE1A8FAFE8B → 8F669F365F24594E` 要求 13 项纹理语义匹配；旧 emissive `D3701FC725106C09 → C6042E3403385D40` 要求完整旧纹理/标量布局，将 512 字节重建为 480 字节并保留对应参数。未知 schema 不改。

游戏参考由 `IGameUnitReferenceReader` 读取 DSAR 未压缩/LZ4 块。包映射偏移 0 是归档内 uint64，偏移 8 是 bundle 内 uint32，偏移 15 是 bundle 编号，不能互换。同 ID 版本分歧为 Ambiguous；修复所用详细参考还校验 LOD 一致性。缺失、歧义或索引不完整不推断参考，不使用全库多数版本。

Compatible 只表示已比对模型的版本匹配，Incompatible 只表示确定的模型版本不匹配。Lua、骨骼、动画及音效不参与模型版本比较；确定不含 Unit 时为 NotApplicable。缺少游戏配置、全部模型没有可用参考或模型版本无法读取时为 Unknown，并显示具体原因；部分模型缺少参考时保留覆盖数量和详情，按有参考的模型给出结果。`HasBlockingStructureIssues` 只聚合确定损坏：补丁 Health 为 Corrupted（头部/索引/载荷/类型分布不可读）或必需伴随缺失，供角标与持久化使用；宽语义的 `HasBlockingIssues` 另含 entry_index、GPU 采样等警告级诊断，仅供修复前校验，不驱动角标。TOC 条目序号、尺寸、伴随范围与 GPU 采样诊断保留在详情和修复前校验，不覆盖模型版本结论。显式参考版本可跳过游戏查询；版本匹配不证明真实游戏运行正常。

## 恢复、提交与缓存

伴随优先从库内主补丁 SHA-256 完全一致、伴随范围完整的副本恢复；多个候选的伴随内容不同即拒绝。游戏恢复要求 Type ID、Resource ID、main bytes、companion size 匹配且伴随载荷唯一，不能给修改后的模型借用同 ID 原版 GPU。

执行在写入闸门内重新生成计划；暂存和复检成功并核对原内容 SHA 后才统一发布。失败或取消反向恢复已提交项，恢复失败明确写入 RecoveryErrors 并保留备份。批量取消保留已完成模组，仅回滚正在处理项。备份独立 sidecar 记录 UTC、SHA 和原文件是否存在，能将新建伴随恢复到不存在；恢复前也备份当前状态。

临时文件结束时清理，备份由历史接口管理。修复后清除 Hash、ResourceTypeIds、BSL 缓存，保持 Mod ID 和 Profile 引用，发布库变更通知。

游戏完整 Unit 定位索引按归档路径、名称、长度、修改/创建时间指纹缓存，不同请求 ID 可复用，归档变化时重建。句柄仅在调用内保留并全部释放。DSAR 解码块使用调用内 16 MiB LRU，每包 128 字节过滤器筛选伴随候选；TOC 索引一次读取。无动作不复制主补丁，已有 GPU/stream 不复制、不整文件加载；实际重建主补丁上限 256 MiB。

检查路径的 patch 报告缓存在分析器内：键含主补丁与 `.stream`/`.gpu_resources` 伴随文件的长度+mtime（伴随缺失也是键的一部分，外部删除伴随文件后重新分析必须反映变化），命中返回深拷贝、缓存本体永不外借，上限 512 条超限整体清空。修复执行、验证与备份路径不缓存；修复或恢复写文件后 mtime 变化自然失效。

## 在线名称

来源为用户指定的 [HD2SDK hashlists](https://github.com/Boxofbiscuits97/HD2SDK-CommunityEdition/tree/main/hashlists)：

- friendlynames.txt 是十进制 ulong 资源 ID，用于 CompatibilityUnit.ResourceName。
- archivehashes.json 是十六进制归档 ID，按补丁文件名前缀查询 CompatibilityPatchReport.ArchiveName，支持省略前导零。
- 两种 ID 独立；名称仅展示，不参与兼容判断和修复。
- 按需整份下载，内存查询，默认一天更新；失败保留旧快照及原哈希，自动重试至少间隔 5 分钟，手动更新可立即重试。
- 数据及 UTC 位于当前 TempPath/compatibility/resource-names.json；两个文件解析并持久化成功后整体发布。超时、网络/格式错误不覆盖旧缓存，取消向上传递。报告保存来源、更新时间和更新错误。
