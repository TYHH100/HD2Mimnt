# 模组 GPU 资源量

模组库卡片显示默认选项的 GPU 资源量；配置页卡片显示该配置保存选项的资源量，顶部显示已启用模组经过资源覆盖后的总计。单位为 MiB（1 MiB = 1,048,576 字节）。悬停查看纹理、模型、其他 GPU 数据及当前配置生效贡献。禁用项保留参考值，不计入总计。

该展示由设置「模组库 → 显示 GPU 资源量」控制，默认关闭：统计需要后台读取大量模组资源，开启后切换页面或配置时可能短暂占用界面线程。关闭时会取消进行中的扫描并清空两页的 GPU 标签。

## 统计范围

- 纹理：只读 Stingray 主数据 `0xC0` 处 DDS 头，按格式、尺寸、实际 mip 数、数组／立方体面及体积深度逐级计算紧凑载荷。BC1/BC4 每 4×4 块 8 字节，其余支持的 BC 格式为 16 字节；末端 mip 也至少一个块。校对 TOC 中 GPU、stream 以及主文件内联载荷的长度。
- 模型：Unit（`0xe0a48d0be9a7453f`）只统计 TOC 的 GPU 段，不把 Unit 主文件和普通 stream 内容全部当作显存。
- 其他：统计其他资源类型声明的 GPU 段。无 GPU 段的 Lua、音效等不增加这一项。
- 所选补丁沿用 `PatchDeploymentPlanner`，包括嵌套选项、直属目录与数字补丁顺序。单模组和整配置均按 `(TypeId, ResourceId)` 保留最终版本，零 GPU 字节的覆盖版本也参与覆盖。不同资源 ID 的相同内容不假设能共享显存。
- 伴随文件缺失、范围不足、未知纹理格式、长度不匹配、补丁或选项读取失败均保留诊断，并显示“未确认”或“部分统计”；部分结果不是总量的可靠下界。

这表示静态资源载荷，**不是单模组实时驻留显存，也不是相对原版新增显存**。未模拟游戏资源引用、流送、纹理质量设置和驱动分配。配置总计也不包括原版游戏和渲染目标。此前 DX11 舰船实测的基线或比例没有写入计算公式。

## 接入与缓存

`ModGpuUsageService` 在 Application 层编排资源读取、选择和汇总。两页通过同一服务获取结果；UI 不直接扫描补丁或访问数据库。`PatchResourceIndexCache` 缓存 TOC 和轻量 DDS 信息，依据文件路径、长度、创建／修改时间失效；每次重新验证伴随文件长度。目录选择和覆盖结果随配置重新计算。

扫描在后台执行。加载列表、导入／更新／修复刷新、配置选项／启停／顺序变更时重新统计；连续配置操作短暂合并。切换配置和新请求取消过期结果，退出等待扫描结束。展示支持简体、繁体、英文实时切换。不新增外部依赖，不修改模组清单或资源文件。

页面切换本身不触发任何统计，常驻页面只切换显示。配置页在没有数据变更事件（`MarkGpuUsageDirty`）且可见内容签名（配置、启用状态、选项、BSL 角色、部署方向）与上次扫描一致时直接跳过，并保留已显示的数字而不是重置为“计算中”；启用/禁用等真实变更仍会重算。

服务层按“模组身份 + 解析后的实际选项 + 清单内容”缓存每个模组的扫描结果，模组库页与配置页共享：同一模组只计算一次，配置页 130 个模组中约 96 个直接复用（其余是选项确实不同）。导入、更新、修复会改写模组的哈希／修改时间，缓存键自动失效，只重算受影响的模组；部署、清理等不改模组的操作不会触发重算。只有手动“刷新”会调用 `ModGpuUsageService.InvalidateScans()` 全量作废，用于拾取绕过管理器直接改写的文件。实测首次调用：配置页 141→38 ms、模组库 105→44 ms（178 个模组）；之后每次约 30–40 ms，主要是读取模组行与合并覆盖关系。

## 验证

2026-11-15：解决方案构建通过；`ModGpuUsageServiceTests`、`ConflictDetectionServiceTests`、`TranslationCatalogTests`、`ProfileViewModelTests` 共 66 项通过，新增 Headless 界面测试 2 项通过。覆盖嵌套选项、显式空选择、缺失目录、末端 BC mip、数组／立方体／体积、数字补丁顺序、部署方向、零字节覆盖、伴随缺失、缓存失效、两页绑定、三语切换和配置切换。已检查两页渲染截图。

只读复核了本次提供的四个实际包，137 个纹理的计算字节数均匹配之前的独立公式结果及 TOC 载荷长度；默认选择沿用各包清单或管理器生成的选项元数据。上述验证没有操作用户数据库、修改模组或重新测量游戏显存。
