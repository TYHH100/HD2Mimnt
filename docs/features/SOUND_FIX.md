# 音效模组修复

入口：**工具 → 音效修复**。先配置游戏目录，再扫描当前模组库；未部署、停用及组件/选项中的补丁也会参与扫描。

扫描不写入模组文件。界面逐模组显示音库、缺失 HIRC 条目和媒体数量、自定义内容及默认跳过原因。选中模组后确认修复；只处理默认安全范围中的内嵌音库，不提供强制修复开关。初始化库、声明 stream/GPU 内容的音库、含较多自定义条目或非武器类新增事件的音库跳过。官方参考缺失或存在多个不同内容时保持未确认。

## 实现及恢复

- `SoundFixService` 从 Repository 获取库内容，通过 `SoundFixInspector` 后台扫描。`IGameSoundBankReader` 复用现有 DSAR 归档读取器和指纹缓存，按音库 ID 查当前官方内容，不使用原工具的固定名称映射表。
- 保留上游的官方 HIRC 重建、按媒体 ID 保留替换音频、DIDX ID 升序与 16 字节对齐、音源 `mem_size` 更新算法。自定义新增事件可能丢失，确认框明确提示。
- 同一补丁的多个安全音库一次性合并；追加新载荷，仅更新相应 TOC 偏移和尺寸。其余资源、原包头及 stream/GPU 伴随文件不重建。
- 修复与恢复均走 `ModService` 写入闸门，保持 Mod ID、Profile 引用和选项；文件提交后更新大小、修改时间并清空内容缓存。扫描后模组或参考内容改变时要求重扫。
- 原文件和校验信息保存于当前应用数据目录 `SoundFixBackups/<Mod ID>/`。备份不在模组内，避免被部署/导出。临时文件在成功、失败、取消时清理；当前模组的文件提交或数据库保存失败会回滚。替换源文件会断开旧的已部署硬链接，不直接修改游戏 data。
- “恢复最近备份”校验备份与修复后的当前文件；若模组后来更新，不覆盖新内容。恢复前也备份当前文件。完成后重新扫描、部署并重启游戏。
