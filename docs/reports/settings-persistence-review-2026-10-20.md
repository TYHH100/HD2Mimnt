# 设置持久化与外观页异常检查（2026-10-20）

## 范围与结论

检查设置分类合并后的保存、恢复默认、语言即时保存、背景选图、设置仓库事务、游戏路径运行时状态及文件日志失败处理。保留工作区其它任务的修改。

本次修复可复现的代码问题，未将运行进程当时的拒绝访问归因为某一种 Windows 权限或文件属性问题，也未修改实际开发/正式数据目录的权限。

## 发现与修复

| 问题 | 修复后的行为 | 证据 |
| --- | --- | --- |
| 日志文件写入失败会从 ILogger 调用链抛出，遮盖原始 SQLite 错误 | 捕获文件 IO 与访问拒绝，写到调试输出；保留数据库失败与旧设置，恢复访问后可再次保存 | 数据库、日志同时只读；独占占用日志；恢复可写后重试 |
| 语言控件恢复同一选择时仍可写库 | 空值与无排队任务时的同一语言代码不提交；只进入外观标签不保存设置 | 四种语言选择下实际点击标签及模拟选中项重建 |
| 跳过同一语言代码会丢失排队中的最后选择 | 有待完成提交时继续排队，保证 auto → en-US → auto 最终为 auto | 新 UI 回归修复前失败、修复后通过 |
| 外观页保存仍校验下载/游戏并写其它分类 | 按当前标签构造保存字典，不受其它标签的无效草稿影响 | 无效游戏路径、下载并发为 0 时外观仍可保存；其它持久化值不变 |
| 外观页恢复默认调用全局重置 | 只恢复明确的外观及语言键，保留游戏、下载、配置与 UI.HiddenEntries | 外观保存和恢复默认隔离回归 |
| 合并标签分多笔保存、重置，中途失败会留下部分提交；重置异常未处理 | 保存使用一次 SetSettingsAsync；多分类重置使用同一数据库事务，成功后才发布快照和运行时事件；失败给出提示 | 在后一个分区注入 SQLite 触发器失败，验证前一个分区数据库、内存与事件均不变 |
| 背景选图/清空先改界面，保存失败向 async void 或命令传播 | 共用保存流程，成功后更新背景；失败保持旧背景并提示 | 注入数据库更新失败，选图和清空均不抛出，背景事件不发布 |
| 游戏路径与自动检测选项分开保存，检测结果先于持久化发布 | Application 服务一次提交两项，成功后更新运行时；游戏分类恢复默认同步清空运行时路径 | 第二项写入失败时数据库和运行时均保留原路径；原有游戏检测测试通过 |

新增的六条设置单元测试和一条快速语言切换 UI 测试先在修复前复现失败，再验证修复通过。其它新增回归覆盖双重只读、日志占用、页面重入和游戏选项事务失败。

扩大回归时同步修正两个旧测试准备问题：存储迁移用例显式创建作为输入的模组目录；反复导入相同内容的偏好用例显式允许重复导入，并检查恢复默认后的真正成功导入，避免把重复拦截当作偏好行为。

## 仍未确认的运行环境因素

用户报告的是 Visual Studio 中断后继续运行仍提示加载或保存失败，因此真实持久化失败不能按“仅调试器中断”忽略。

检查时，`HD2Mimnt.dev` 的数据库、WAL、SHM 和 `Logs/application.log` 均没有只读属性；当前工具进程能够以写权限打开这些已有文件而不写入内容。该结果只证明检查时工具进程的访问情况，不能证明故障时被调试进程具有相同访问状态。

原始堆栈没有 `SqliteExtendedErrorCode`，也没有故障时的进程级文件访问结果。目前不能确定是临时访问限制、数据库辅助文件/目录权限，还是其它运行环境因素。保留 SQLite 原始失败，不删除或重新创建用户数据库，也不自动改权限、切换数据目录或将保存失败当作成功。
