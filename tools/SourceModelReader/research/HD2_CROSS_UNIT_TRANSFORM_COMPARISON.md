# HD2 Cross-Unit Transform Comparison

Date: 2026-11-05

Status: diagnostic tool and synthetic regression tests added; local test execution and fresh real-Unit report generation are pending.

## Purpose

Compare the same uniquely resolved TransformInfo bone names across these three selected real-game Unit reports:

- FS-05 lower body: `210fb2f60f8308ea`
- FS-05 torso / left arm: `324fb206612ce4f7`
- Avatar CompositeUnit: `4d1c334d294dfa97`

The comparison checks:
- resolved parent-bone names;
- stored local `position`, `rotation_3x3`, and `scale`;
- stored `matrix_4x4_raw` values, including linear and translation component differences;
- whether each named TransformInfo is actively referenced by the selected mesh.

Only unique, resolved names are compared. Ambiguous and unresolved names remain excluded instead of being guessed.

## Run

From `tools/SourceModelReader`:

```powershell
py -3 -m unittest discover -s tests -p "test_hd2_unit_transform_comparison.py" -v
```

Then run the comparison. The three JSON reports generated by the skinning audit batch are used by default:

```powershell
py -3 .\research\compare_hd2_unit_transforms.py
```

Optional explicit inputs:

```powershell
py -3 .\research\compare_hd2_unit_transforms.py `
    --lower-body .\research\skinning_audits\fs05_lower_body.json `
    --torso-left-arm .\research\skinning_audits\fs05_torso_left_arm.json `
    --avatar .\research\skinning_audits\avatar_composite.json
```

The default tolerance is `1e-4`. Outputs:

- `research/skeleton_comparison/hd2_unit_transform_comparison.md`
- `research/skeleton_comparison/hd2_unit_transform_comparison.json`

The Markdown report is the shareable summary. The JSON output contains the complete pairwise rows and the names common to all three Units. A pair with no shared unique names is explicitly marked `no_shared_unique_names` and contributes to an overall `warning`; this prevents an empty comparison from appearing to pass.

## Interpretation

A small or zero numeric difference across these selected Unit samples is evidence that their stored TransformInfo entries agree under the compared representation. It does not independently establish:
- universal axis orientation, handedness, or unit scale;
- that all raw matrices represent the same semantic space across every Unit type;
- inverse-bind semantics or runtime GPU skinning behavior;
- animated deformation;
- correctness of a Source-to-HD2 retarget map.

The existing Unit parser separately validates the relationship between each Unit's reconstructed hierarchy matrix and its stored TransformInfo matrix, and checks active BoneInfo palette matrices against the candidate `MeshWorld * inverse(BoneWorld)` formula. This new tool adds the missing cross-Unit name-based numeric comparison; it does not replace those validations.
